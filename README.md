# 뭐라고

한글로 들리는 대로 치면 원래 일본어를 찾아주는 iPadOS 앱.

애니를 보다 걸린 대사를 한글로 검색하면 원문이 나오고, 그게 모여 그 화의 교재가 되고,
쉐도잉해서 결국 자막 없이 알아듣게 되는 것을 목표로 한다.

기존 한글-일본어 변환기는 "다이죠부"에 `ダイジョブ`를 뱉는다.
`大丈夫`를 찾아주는 도구가 없어서 만든다.

## 현재 상태

M0 스파이크. 앱 코드는 아직 없고, 복원 규칙이 실제로 통하는지 재는 단계다.

## 왜 어려운가

한글 음차는 일본어의 정보를 다섯 가지 잃는다.

| 잃는 것 | 예 | 문제 |
|---|---|---|
| 장음 | だいじょ**う**ぶ → "다이죠부" | う가 증발 |
| 탁음/청음 | だ / た → "다" 또는 "타" | 한국어 어두에 유성음이 없음 |
| 촉음 | い**っ**しょ → "잇쇼" | 받침 ㅅ으로 뭉개짐 |
| 발음 ん | せ**ん**ぱい → "센빠이" | 받침 ㄴ·ㅁ·ㅇ 아무거나 |
| つ | つ → "츠" / "쓰" / "스" | 셋 다 쓰인다 |

가나에서 한글로 가는 길은 답이 하나지만, 반대 방향은 답이 여럿이다.
그래서 정답 하나를 고르지 않고 후보를 모두 펼친 뒤 사전으로 걸러낸다.

## 복원 파이프라인

```
한글 음차
  → 음절 분해         초성·중성·종성
  → 로마자 후보 생성   탁음 모호 · 요음 · 촉음 · 발음
  → 장음 변형 조합
  → 가나 후보
  → 사전 대조         ← 여기서 대부분 걸러진다
  → 모델              ← 후보가 둘 이상 남을 때만
```

모델은 마지막에만 부른다. 그래서 Apple Intelligence를 지원하지 않는 기본 iPad에서도
검색이 동작한다. 폴백이 곧 시장 확대다.

중간 표현으로 훈령식 로마자(`si`, `ti`, `zyo`)를 쓴다. 헵번식(`shi`, `chi`, `jo`)과 달리
자음과 모음이 예외 없이 맞아떨어져서, 오십음도를 손으로 적지 않고 행 × 단으로 생성할 수 있다.

## 구성

폴더 구조는 SpringLab 을 따른다. 역할별로 나누고, 앱에 실리지 않는 것은 `Tools/` 로 뺀다.

```
Mworago/
  Model/
    Hangul.swift          한글 음절 분해. U+AC00 기반 나눗셈 세 번
    KanaTable.swift       훈령식 로마자 ↔ 가나
  Store/
    JMDict.swift          JMdict XML 스트리밍 파서와 읽기 색인
    FrequencyList.swift   애니 도메인 빈도 목록
  Runner/
    Transliterator.swift  한글 → 가나 후보 생성
    Deinflector.swift     활용형을 사전형으로 되돌리기
    Ranker.swift          살아남은 후보 줄 세우기
MworagoTests/             테스트 43개
Tools/
  SpikeRunner/            M0 측정 도구
  fetch-jmdict.sh         JMdict 내려받기
  data/                   측정 케이스와 사전 원본
docs/                     기록
```

## 실행

```sh
swift test                  # 테스트
./Tools/fetch-jmdict.sh     # 사전 내려받기, 약 10MB
swift run SpikeRunner       # 측정
```

## M0 결과

**판정 통과.** 기준 40/50, 실측 **47/50 (94%)**. 3위 안 49/50 (98%).

| | 규칙+사전 | 순위 재설계 | 도메인 빈도 |
|---|---|---|---|
| 재현율 — 정답이 후보 안에 있는가 | 100% | 100% | 100% |
| **정확도 — 1위가 정답인가** | 90% | 92% | **94%** |
| 3위 안 | 96% | 96% | **98%** |
| 쿼리 | 0.03ms | 0.05ms | 0.09ms |

50개 표본에서 1~2건 차이는 노이즈 범위다. 이 숫자를 "꾸준히 개선"으로 읽으면 안 된다.
재현율 100%도 규칙을 설계하며 케이스 태그를 참고했으므로 편향이 있다.

### 배운 것

**신문 빈도는 애니에서 잡음이다.** JMdict의 빈도 태그는 신문 말뭉치 기준이라
`遺体`(4680위)가 `痛い`(592위)를 밀어낸다. 가중치를 훑어 보니 상위 조합이 일관되게
JMdict 무게를 0 쪽으로 밀었다.

**빈도 목록에는 사전형만 실린다.** 그대로 쓰면 `疲れた`가 0점을 받아 `疲れる`에게 진다.
표기와 읽기를 같은 활용 규칙으로 함께 되돌려 사전형의 빈도를 물려받게 해야 공평하다.

**가중치는 손으로 정하지 않는다.** `SpikeRunner --sweep`이 768개 조합을 훑어 고른다.

자세한 분석은 [docs/M0-결과.md](docs/M0-결과.md).
