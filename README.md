# 뭐라고

한글로 들리는 대로 치면 원래 일본어를 찾아주는 iPadOS 앱.

애니를 보다 걸린 대사를 한글로 검색하면 원문이 나오고, 그게 모여 그 화의 교재가 되고,
쉐도잉해서 결국 자막 없이 알아듣게 되는 것을 목표로 한다.

기존 한글-일본어 변환기는 "다이죠부"에 `ダイジョブ`를 뱉는다.
`大丈夫`를 찾아주는 도구가 없어서 만든다.

## 현재 상태

M0 스파이크. 앱 코드는 아직 없고, 복원 규칙이 실제로 통하는지 재는 단계다.

## 왜 어려운가

한글 음차는 일본어의 정보를 다섯 가지 잃는다.

| 잃는 것 | 예 | 문제 |
|---|---|---|
| 장음 | だいじょ**う**ぶ → "다이죠부" | う가 증발 |
| 탁음/청음 | だ / た → "다" 또는 "타" | 한국어 어두에 유성음이 없음 |
| 촉음 | い**っ**しょ → "잇쇼" | 받침 ㅅ으로 뭉개짐 |
| 발음 ん | せ**ん**ぱい → "센빠이" | 받침 ㄴ·ㅁ·ㅇ 아무거나 |
| つ | つ → "츠" / "쓰" / "스" | 셋 다 쓰인다 |

가나에서 한글로 가는 길은 답이 하나지만, 반대 방향은 답이 여럿이다.
그래서 정답 하나를 고르지 않고 후보를 모두 펼친 뒤 사전으로 걸러낸다.

## 복원 파이프라인

```
한글 음차
  → 음절 분해         초성·중성·종성
  → 로마자 후보 생성   탁음 모호 · 요음 · 촉음 · 발음
  → 장음 변형 조합
  → 가나 후보
  → 사전 대조         ← 여기서 대부분 걸러진다
  → 모델              ← 후보가 둘 이상 남을 때만
```

모델은 마지막에만 부른다. 그래서 Apple Intelligence를 지원하지 않는 기본 iPad에서도
검색이 동작한다. 폴백이 곧 시장 확대다.

중간 표현으로 훈령식 로마자(`si`, `ti`, `zyo`)를 쓴다. 헵번식(`shi`, `chi`, `jo`)과 달리
자음과 모음이 예외 없이 맞아떨어져서, 오십음도를 손으로 적지 않고 행 × 단으로 생성할 수 있다.

## 구성

```
Sources/MworagoCore/
  Hangul.swift          한글 음절 분해. U+AC00 기반 나눗셈 세 번
  KanaTable.swift       훈령식 로마자 ↔ 가나
  Transliterator.swift  한글 → 가나 후보 생성
  JMDict.swift          JMdict XML 스트리밍 파서와 읽기 색인
Sources/SpikeRunner/    M0 측정 도구
Tests/                  테스트 23개
Data/spike-cases.tsv    측정 케이스 50개
Scripts/fetch-jmdict.sh JMdict 내려받기
```

## 실행

```sh
swift test                                    # 테스트
./Scripts/fetch-jmdict.sh                     # 사전 내려받기, 약 10MB
swift run SpikeRunner Data/spike-cases.tsv    # 측정
```

## M0 결과

| 지표 | 값 |
|---|---|
| 재현율 — 정답이 후보 안에 있는가 | 50/50 (100%) |
| **1위 표기까지 일치 — 판정 기준** | **42/50 (84%)** |
| 1위 읽기 일치 | 40/50 (80%) |
| 3위 안 | 43/50 (86%) |
| 사전에 아예 없음 | 6/50 (12%) |
| 쿼리 시간 | 평균 0.03ms |
| 후보 수 | 평균 8개, 최대 128개 |

판정 기준은 40/50이었고 42/50으로 넘겼다. **모델 없이 규칙과 사전만으로 통과했다.**

재현율 100%는 규칙을 설계하며 케이스 태그를 참고했으므로 편향이 있다.
"규칙이 훌륭하다"가 아니라 "알려진 실패 유형은 덮었다"로 읽어야 한다.

후보가 평균 8개라는 점이 그다음으로 중요하다. 사전 조회가 사실상 공짜라
기기에서 즉시 응답이 나온다.

### 놓친 8건이 말해주는 것

실패는 음차 규칙 탓이 아니었다. 여덟 중 여섯이 **활용형**이다.

| 입력 | 정답 | 사전에 있는 형태 |
|---|---|---|
| 야메로 | やめろ | やめる |
| 키에로 | 消えろ | 消える |
| 이소게 | 急げ | 急ぐ |
| 요캇타 | 良かった | 良い |
| 다마레 | 黙れ | 黙る |
| 마지데 | マジで | マジ + 조사 で |

JMdict는 사전형만 싣는다. 그런데 애니 대사는 명령형·과거형이 대부분이다.
**활용형 역변환**이 다음 과제이고, 이건 규칙으로 풀린다.

나머지 둘(이타이 → 痛い, 츠기 → 次)은 동음이의어 줄 세우기 문제다.
遺体·異体가 痛い보다 위로 온다. 빈도 점수를 손보거나 모델을 부를 자리다.
