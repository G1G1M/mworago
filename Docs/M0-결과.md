# M0 스파이크 결과 — 사전만으로 어디까지 되나

**판정: 통과.** 기준 40/50, 실측 42/50 (84%).

## 무엇을 쟀나

가설: *한글 음차를 규칙으로 가나 후보로 펼치고 JMdict로 거르면, 모델 없이도 정답이 1위로 올라온다.*

이게 참이어야 Apple Intelligence 미지원 기기에서도 검색이 돌아간다. 폴백이 곧 시장이다.

케이스 50개(`Data/spike-cases.tsv`)는 구현 전에 봉인했다. 애니 빈출 표현으로, 한글 음차가
정보를 잃는 다섯 유형(장음·탁음모호·촉음·발음ん·つ)에 태그를 달아 두었다.

## 숫자

| 지표 | 값 |
|---|---|
| 재현율 (후보에 정답 가나가 있음) | 50/50 (100%) |
| **1위 표기까지 일치** | **42/50 (84%)** |
| 1위 읽기 일치 | 40/50 (80%) |
| 3위 안 | 43/50 (86%) |
| 사전에 아예 없음 | 6/50 (12%) |
| 후보 수 | 평균 8개 · 최대 128개 |
| 쿼리 | 0.03ms |
| 사전 적재 | 21.8만 표제항 |

재현율 100%는 편향된 숫자다. 규칙을 설계하며 케이스 태그를 봤다. "규칙이 완벽하다"가 아니라
"알고 있던 실패 유형은 덮었다"로 읽어야 한다. 모르는 유형은 케이스를 늘려야 드러난다.

후보가 평균 8개뿐인 건 예상 밖의 좋은 소식이다. 사전 조회 비용이 사실상 0이라 기기에서 즉시 답한다.

## 실패 8건 — 세 무리

### ① 활용형 (5건) — 야메로 · 요캇타 · 다마레 · 키에로 · 이소게

전부 "사전에 아예 없음". JMdict는 기본형만 싣는다. `やめる`는 있어도 `やめろ`는 없다.

문제는 이게 주변부가 아니라는 점이다. **애니 대사는 대부분 활용형이다** — 명령형, 과거형, て형.
사전을 날것으로 쓰면 앱이 정확히 노리는 문장에서 가장 많이 터진다.

→ 활용 역변환(deinflection)이 필요하다. 규칙 20~30개로 대부분 덮인다.

### ② 동음이의 순위 (2건) — 이타이 · 츠기

```
이타이 → 遺体(유체) 1위, 痛い(아프다) 2위
츠기   → 机(책상) 1위,  次(다음) 는 아래
```

JMdict의 빈도 태그(news1·nf05)는 **신문 말뭉치** 기준이다. 신문에서는 "유체"가 "아프다"보다 흔하다.
애니에서 "이타이"는 사실상 전부 `痛い`다.

**신문 빈도 ≠ 애니 빈도.** 순위를 JMdict 점수에만 맡기면 안 된다. v1.0 설계에 직접 영향.

### ③ 카타카나 + 조사 (1건) — 마지데

`マジで` = `まじ` + 조사 `で`. 낱말 단위 조회로는 안 잡힌다. 조사 분리가 필요하다.

## 자잘하지만 기록해 둘 것

- `혼토니` → 정답 읽기는 `ほんとうに`인데 사전 1위는 축약형 항목 `ほんとに`다. 표기(本当に)는 맞아서
  통과했지만, 읽기 지표(80%)와 표기 지표(84%)의 차이가 대부분 이것이다. 이표기 통합이 필요.
- `키오츠케테`는 조사 `を`를 모든 "오"에 후보로 넣은 덕에 맞았다. 대신 후보 순위가 17위까지 밀렸다가
  사전이 정리해줬다. 후보를 넉넉히 펼치고 사전이 좁히는 설계가 실제로 작동한다는 증거.

3. **역할어 30개 · 표현 설명 10개** — 오늘 검증한 건 3층 중 1·2층(규칙·사전)뿐이다.
   3층(모델)은 아직 손대지 않았다.
